# API guide

An API request has a method (such as GET or POST), an address, and sometimes a JSON body. Use Postman to send these requests; the [Phase 1 demo](phase1-demo.md) walks through them.

Course requests start with `http://127.0.0.1:8081`. Student and Enrollment requests start with `http://127.0.0.1:8082`. Add a path from the tables below to the appropriate address.

Replace `{courseId}`, `{studentId}`, and `{enrollmentId}` with the IDs returned when you create those records. These IDs are UUIDs: unique values generated by the server.

## Course requests

| Method | Path | What it does |
| --- | --- | --- |
| POST | /api/v1/courses | Creates a Course. It is active by default. |
| GET | /api/v1/courses | Lists active Courses, one page at a time. |
| GET | /api/v1/courses/{courseId} | Reads one Course, including an archived Course. |
| PUT | /api/v1/courses/{courseId} | Updates an existing Course. If `active` is omitted, its current status stays the same. |
| PATCH | /api/v1/courses/{courseId}/status | Changes active status. Use `{"active":false}` to archive or `{"active":true}` to reactivate. |

A JSON body for creating a Course:

```json
{
  "courseCode": "DEMO201",
  "title": "Fictitious Cloud Course",
  "description": "Demo only",
  "credits": 3
}
```

Archiving keeps the Course and its existing enrollments, but blocks new enrollments. This phase does not provide a Course deletion request.

## Student requests

| Method | Path | What it does |
| --- | --- | --- |
| POST | /api/v1/students | Creates a Student. |
| GET | /api/v1/students | Lists Students, one page at a time. |
| GET | /api/v1/students/{studentId} | Reads one Student. |
| PUT | /api/v1/students/{studentId} | Updates an existing Student. |

A JSON body for creating a Student:

```json
{
  "studentNumber": "DEMO201",
  "name": "Fictitious Student",
  "email": "demo201@example.invalid"
}
```

PUT changes an existing record; it does not create a missing one. This phase does not provide a Student deletion request. See [field rules](#field-rules) for required values and length limits.

## Enrollment requests

| Method | Path | What it does |
| --- | --- | --- |
| POST | /api/v1/students/{studentId}/enrollments | Enrolls the Student in the Course named in the body. |
| GET | /api/v1/students/{studentId}/enrollments | Lists that Student's enrollments, one page at a time. |
| GET | /api/v1/students/{studentId}/enrollments/{enrollmentId} | Reads one enrollment belonging to that Student. |
| DELETE | /api/v1/students/{studentId}/enrollments/{enrollmentId} | Drops that Student's enrollment. Success returns 204 with no response body. |

To enroll a Student, replace the placeholder below with the Course ID:

```json
{
  "courseId": "COURSE_UUID"
}
```

An Enrollment response contains `id`, `studentId`, `courseId`, and `enrolledAt`. The date/time uses UTC, for example `2026-10-04T19:00:00Z`.

Reading, listing, and dropping existing enrollments do not fetch Course details. They can work while Course is stopped. Using the wrong Student ID, or an enrollment that is missing or already dropped, returns **404**.

## Field rules

The server removes surrounding spaces before checking and storing text values.

| Field | Rule |
| --- | --- |
| Course code and Student number | Required, unique, stored in uppercase; up to 32 characters. |
| Course title and Student name | Required; up to 160 characters. |
| Course description | Optional; up to 2,000 characters. |
| Student email | Required, unique, valid email format, stored in lowercase; up to 254 characters. |
| Course credits | A whole number from 1 to 6. |

## Service information and response links

Send GET `/api/v1/info` to either service to see its name, active profile, and banner (a short configured message).

Successful POST requests return **201** and a `Location` header pointing to the new record. The header contains a relative path, such as `/api/v1/courses/UUID`; add the service address to make a complete URL.

Single Course and Student responses include `_links` with related request paths. Course links are `self` (the current record), `collection` (the list), and `status`. Student links are `self`, `collection`, and `enrollments`. These links are part of the API response objects, not the JPA database entities.

## Lists, pages, and search

List requests work without extra parameters. To choose which records or page you want, add query parameters after `?` and join multiple parameters with `&`.

| Parameter | Where it applies | Meaning |
| --- | --- | --- |
| active | Course list | `true` selects active Courses (the default); `false` selects archived Courses. |
| search | Course list | Finds text in the Course code or title, ignoring uppercase/lowercase differences. |
| page | All lists | Page number. The first page is `0`. |
| size | All lists | Records per page. Default `20`; allowed range `1` to `100`. |

For example, `/api/v1/courses?search=cloud` searches active Courses for `cloud`. Use `/api/v1/students?page=1` to get the second page of Students.

An empty list looks like this:

```json
{
  "content": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0
}
```

`content` contains the records. The other fields show the current page, page size, total record count, and total page count. Sorting is fixed; custom sorting is not supported.

## Errors and status codes

Send JSON bodies with the `Content-Type: application/json` header.

| Status | Meaning in this project |
| --- | --- |
| 200 | The read or update succeeded. |
| 201 | A new record was created. |
| 204 | An enrollment was dropped; there is no response body. |
| 400 | Input is invalid, such as bad JSON, an invalid UUID, or an invalid page value. |
| 404 | The requested Course, Student, enrollment, or path was not found. |
| 405 | The request method is not supported at that path. |
| 409 | The request conflicts with a rule, such as a duplicate record or enrollment in an inactive Course. |
| 415 | The body uses an unsupported content type. |
| 500 | An unexpected application or database failure occurred. |
| 503 | Enrollment could not check Course because it was unavailable, too slow, or returned an unusable response. |

Errors use the JSON `ProblemDetail` format. For example, enrolling the same Student in the same Course twice returns:

```json
{
  "type": "about:blank",
  "title": "Conflict",
  "status": 409,
  "detail": "Student is already enrolled in this course.",
  "instance": "/api/v1/students/UUID/enrollments",
  "code": "ALREADY_ENROLLED"
}
```

`detail` explains the error, `instance` identifies the request path, and `code` gives a stable name that tests or client code can check. Input validation errors can also include `fields`, which maps invalid field names to readable messages.

Unexpected failures return a general message without database commands, secrets, or internal error traces. Set the `Accept-Language` header to `es` for Spanish error messages. Unsupported languages use English. The error codes stay the same in every language.
